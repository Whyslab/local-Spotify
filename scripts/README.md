# Скрипты

## analyze_audio.py — измерить фонотеку

У 1109 треков нет ни жанра, ни BPM. Сортировать нечем — кроме самого звука.
Скрипт слушает каждый трек и записывает темп, энергию, яркость и тональность,
чтобы очередь можно было собирать не случайно.

### Запуск

```bash
# так, как задумано: с потолком памяти и пониженным приоритетом
systemd-run --user --scope -p MemoryMax=1500M \
  nice -n 10 .venv/bin/python scripts/analyze_audio.py --jobs 3
```

Зависимости стоят отдельно от сервиса — librosa тянет numba и scikit-learn,
а сервису они не нужны:

```bash
.venv/bin/pip install -r scripts/requirements-analysis.txt
```

### Сколько это займёт

Измерено на этой машине (i5-6300U, 2 ядра): **около 3 секунд на трек**,
то есть примерно **час на всю фонотеку** в один процесс и **порядка 55 минут**
на двух. Пиковая память одного процесса — **376 МБ**, поэтому три помещаются
в лимит 1500 МБ, а без лимита earlyoom скорее убьёт браузер, чем анализ.

Оценка в плане работ была 15–30 минут. Она оказалась вдвое оптимистичной.

### Прогон можно прерывать

Каждый трек записывается сразу и опознаётся по пути и хешу содержимого.
Прерванный прогон продолжается с места остановки, а неизменившийся трек не
измеряется повторно. Убить процесс безопасно.

С `--jobs` больше единицы выход не мгновенный: уже начатые треки дописываются,
и это занимает секунды. Остальные снимаются сразу.

```bash
scripts/analyze_audio.py --limit 50      # остановиться после 50 треков
scripts/analyze_audio.py --only ФАЙЛ     # один файл
scripts/analyze_audio.py --force         # пересчитать всё заново
```

### Ночью, само

```bash
sed -e "s|%REPO%|$PWD|g" -e "s|%JOBS%|1|g" \
  deploy/music-analysis.service.template > ~/.config/systemd/user/music-analysis.service
cp deploy/music-analysis.timer.template ~/.config/systemd/user/music-analysis.timer
systemctl --user daemon-reload
systemctl --user enable --now music-analysis.timer
```

Один процесс, а не три: ночной проход обычно только пересчитывает хеши и
занимает меньше минуты, а после обновления librosa три процесса компилируют
кэш разом и подходят вплотную к потолку памяти — на машине, где свободно
меньше двух гигабайт, это стоит дороже сэкономленного времени. Три процесса
остаются для ручного прогона всей фонотеки с нуля.

Новый трек измеряется сразу при добавлении — тем же способом, в своей области
с тем же лимитом, — так что таймер нужен только для догона того, что появилось
до его включения.

### Что именно измеряется

| | |
| --- | --- |
| **темп** | ударов в минуту; половинный и двойной темп считаются одним и тем же |
| **энергия** | среднеквадратичная громкость — насколько трек «давит» |
| **яркость** | спектральный центроид: два трека одного темпа и громкости всё равно разные, если один басовый, а другой в тарелках |
| **тональность** | нота и лад, по корреляции хромаграммы с профилями Крумхансль–Шмуклера |

Анализируется **середина трека**, 90 секунд. Этого с запасом хватает на темп и
тональность, память ограничена независимо от длины трека, а вступление и
концовка — наименее показательные части песни для обоих.

Декодирует **ffmpeg**, а не встроенный загрузчик librosa: тот читает через
libsndfile, который не умеет AAC, а почти вся фонотека в `.m4a`.

## export_shelves.py — полки главной в подборки

Полки главной («В машину», «Разогнаться», «На работу», «Поярче», «Может
понравиться») считаются на лету, и на телефоне их нет вовсе: Amperfy видит
только то, что Navidrome нашёл в фонотеке, а там подборка — это файл. Скрипт
пересобирает те же пять полок в файлы `★ ....m3u` в корне фонотеки.

Альбомы с главной не выгружаются: альбом Navidrome и так знает по тегам, и
подборка из него была бы второй копией того же.

### Руками

```bash
.venv/bin/python scripts/export_shelves.py
```

Печатает по строке на полку и код возврата: `0` — записана хотя бы одна,
`1` — ни одной. Полка меньше восьми треков пропускается, и вчерашний файл
остаётся на месте: вчерашняя подборка лучше пустой.

### Ночью, само

Позже разбора звука, а не раньше: полки строятся из `audio_features`, поэтому
запуск до анализа собрал бы их по вчерашним измерениям. Таймер стоит на 04:30,
анализ — на 03:30.

```bash
# API_TOKEN нужен только чтобы adder.config вообще импортировался;
# путь фонотеки берётся из adder/.env, если он там задан.
LIBRARY=$(API_TOKEN=unused .venv/bin/python -c 'from adder import config; print(config.LIBRARY)')
sed -e "s|%REPO%|$PWD|g" -e "s|%LIBRARY%|$LIBRARY|g" \
  deploy/music-shelves.service.template > ~/.config/systemd/user/music-shelves.service
cp deploy/music-shelves.timer.template ~/.config/systemd/user/music-shelves.timer
systemctl --user daemon-reload
systemctl --user enable --now music-shelves.timer
```

Служба ходит только в две папки — корень фонотеки и `adder/playlist-history`, —
поэтому `%LIBRARY%` в шаблоне обязателен: без подстановки `ProtectHome=read-only`
не даст записать ни одного файла.

### Правки в подборках со звездой затираются

Файл `★ ...` пересобирается целиком при каждом запуске. Переставленный трек,
удалённый трек, дописанная строка — всё это исчезнет следующей ночью. Прежнее
содержимое уходит в `adder/playlist-history/★ .../`, так что затёртую правку
оттуда можно достать — но история хранит двадцать последних версий, а запуск
каждую ночь свой, то есть примерно три недели. Постоянной подборке лучше дать
своё имя, без звезды: приставка `★` и означает «этот файл принадлежит скрипту».
