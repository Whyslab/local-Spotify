### Скорость (этап 3, 08.10)

Что сделано (каждое — с тестом механизма и замером до/после):

- **Ответы и кэш:** gzip для текстовых ответов, файлы с отпечатком `?v=` — на год в кэше браузера (`b4fdb0d`).
- **Обложки, клиент:** просятся, когда список остановился, видимые первыми, по 4 разом (по HTTP/2 — 8),
  ушедшая с экрана строка отменяет свой запрос (`51774c3`, `8cece94`, `085b671`, `ad0e08e`, `82f0f19`);
  обложки экрана приходят одним запросом `POST /api/covers` (`e434dce`, `0809d1a`); картинки находок и фото
  артистов идут через ту же очередь (`de8ebee`, `e952220`, `a6a82f8`, `bbe1c85`).
- **Обложки, сервер:** миниатюры — ffmpeg не больше двух разом, кэш на диске, тёплый запрос без разбора тегов,
  заготовка при добавлении и ночью (`677777b`, `636ce7e`).
- **Поиск:** запрос сразу после последней буквы (было 300 мс у фонотеки и 120 у общего), после минуты
  простоя отвечает старый индекс и следом новый, группировка один раз на индекс (`c7127a3`, `260bf67`,
  `220b35a`, `78ad0c4`, `41f8a10`).
- **Прокрутка:** строки фонотеки пропускаются пачками по 50, а не по одной (`fe30d5e`).
- **Service worker:** отвечает сразу, копию пишет после (`1abd4e6`); телефон проверен пользователем.
- **Защита:** тело любого POST/PUT/PATCH/DELETE ограничено 2 МБ ещё до чтения, считается и для chunked (`b441448`).

Рецензия (`code-reviewer`, две итерации, затем повторная — APPROVE). Исправлено: у пачки обложек не было
отмены и тайм-аута (`834ac6f`); строка, вернувшаяся к идущей пачке, занимала место (`0a34f4d`, `1d48226`);
длины картинок в ответе пачки не сверялись (`2e30542`); прокси задержки в `measure_ui.py` не закрывал сокеты
(`d8dec85`, `544a19a`); неверный путь в пачке ронял её целиком (`0f9a1c5`); тип картинки — только из
списка изображений (`20de977`). Не исправлялось по решению: неверный путь помнится как «нет обложки»
10 минут; обложка, которую ffmpeg не смог сделать, в пачке всегда «позже» (её просят по одной).

Рецензия остальных коммитов этапа (`code-reviewer`, 08.10): **ограничение тела в 2 МБ (`b441448`) резало
загрузку фото артиста** — фото с телефона на 3–6 МБ получало 413, хотя принимается до 8 МБ; исправлено
(`0bbc70d`), тест проверяет, что у каждого маршрута с файлом свой предел (`a32f499`). Комментарий про паузу
поиска (`7389548`). Не исправлялось по решению: повторный 413 после начала ответа (сейчас ни один маршрут так

Safari протокол страницы, открытой через service worker (в Chromium — да; иначе телефон берёт 4 места, а не 8).
Рецензия безопасности этапа (`security-reviewer`): высоких и средних нет; выход за фонотеку через

### Docker или systemd

Решено оставить systemd. У Docker для этого проекта были бы плюсы: одинаковые версии ffmpeg и Deno
из коробки, установка на NAS (Synology, Unraid), где нет пользовательских юнитов systemd, и общий
`docker-compose` с Navidrome. Но здесь они перевешиваются минусами: `COOKIES_FROM_BROWSER` читает
профиль браузера на хосте, что из контейнера неудобно; анализ аудио ограничивает память через
`systemd-run`, в контейнере этого нет; yt-dlp приходится обновлять часто, а в Docker это пересборка
образа вместо `pip install -U`; десктоп-оболочка и медиаклавиши живут на хосте. Для одной домашней
машины с systemd Docker добавил бы слой без выигрыша.

### H4. Ошибки yt-dlp: причина теряется, классификация неверная
- **Где:** `adder/app.py:531`, `adder/app.py:551` (`p.stderr.strip()[-300:]`), `adder/app.py:740-777` (`classify_error`).
- **Суть (проверено на реальных сообщениях yt-dlp):**
  - В задачу пишутся последние 300 символов stderr. Строка `ERROR:` длинная, поэтому пользователь видит хвост вида `...for tips on effectively exporting YouTube cookies`, а сама причина («Sign in to confirm you're not a bot») обрезана.
  - `ffprobe and ffmpeg not found` → `youtube_not_found` (из-за подстроки «not found»): пользователю говорят, что видео нет.
  - `Private video` для видео с `503` в ID → `network_error` и три бессмысленных повтора: подстроки `502/503/504` ищутся где угодно, включая ID и URL.
  - Rate limit обрабатывается непоследовательно: `Unable to download API page: HTTP Error 429` → `download_error` (повтор), `HTTP Error 429: Too Many Requests` → `unknown_error` (без повтора), `This content isn't available, try again later` (так YouTube сообщает об ограничении сессии) → `youtube_not_found` (без повтора).
  - Бот-проверка и возрастное ограничение → `unknown_error`, без подсказки про `COOKIES_FROM_BROWSER`.
- **Фикс:** брать из stderr последнюю строку `ERROR:` (если её нет — хвост, как раньше). В `classify_error` добавить типы `dependency_error` (ffmpeg — постоянная), `rate_limited` (429 / too many requests / try again later — повторяемая) и `youtube_auth_required` (бот-проверка, возраст, members-only — постоянная). HTTP 5xx сопоставлять только по `http error 50x`. К ошибке бот-проверки добавлять подсказку про `COOKIES_FROM_BROWSER`.
- **Не меняется:** экспоненциальный backoff (2 с, 4 с) — для rate limit он коротковат, см. M3.

### H5. Отсутствие ffmpeg/ffprobe и Deno не обнаруживается
- **Где:** `adder/app.py:1014-1045` (`lifespan`), `adder/app.py:1298-1337` (`/health`).
- **Суть:** сервис стартует «healthy», а каждая задача потом падает на постобработке. Про Deno вообще ничего нигде нет.
- **Фикс:** при старте проверить `shutil.which` для `ffmpeg`/`ffprobe` (без них — `ERROR` в логе и `/health` = `unhealthy` с полем `ffmpeg: missing`) и для `deno` (без него — `WARNING` в логе и поле `js_runtime` в `/health`, но статус healthy: часть видео может скачаться и без него).

### H6. Небезопасные имена файлов из метаданных YouTube
- **Где:** `adder/app.py:180-184` (`sanitize_filename`), использование в `adder/app.py:839-841`.
- **Суть:** имя исполнителя — это название канала, то есть недоверенные данные. Проверено:
  - `sanitize_filename("..")` → `".."` → `LIBRARY / ".." / "Singles"` — запись **за пределы библиотеки**;
  - заголовок из одних запрещённых символов (`"?"`) → `""` → файл `.m4a` — скрытый, Navidrome его не покажет;
  - имя, начинающееся с точки, — тоже скрытое;
  - длинное имя (эмодзи/кириллица) может превысить 255 байт → `OSError: File name too long` → задача падает как `unknown_error`.
- **Фикс:** в `sanitize_filename` убирать ведущие/хвостовые точки и пробелы, обрезать до 200 байт UTF-8 по границе символа, пустой результат превращать в `Unknown`.

### H7. Воркер-поток умирает от неожиданного исключения
- **Где:** `adder/app.py:987-1010` (`worker`), обработчики ошибок в `process` (`adder/app.py:904-984`).
- **Суть:** если внутри обработчика ошибки падает сам `task_update` (например, `database is locked`) или что-то выше по стеку бросает исключение, оно выходит из `worker()` и **поток завершается**. После `MAX_WORKERS` таких случаев очередь встаёт навсегда, `/health` остаётся «healthy», а URL остаётся в `PROCESSING_URLS`: повторная отправка той же ссылки молча игнорируется до перезапуска.
- **Фикс:** в `worker()` оборачивать `process()` в `try/except Exception`: логировать с трейсбэком, по возможности помечать задачу `error`, всегда освобождать URL и продолжать цикл.
